## v1.5.0 · 界面默认英文，中文可切

界面文案从「写死在中文里」改成走词表：**默认英文**，设置里一键切中文，同一份前端、同一个二进制，不需要两套构建。

### 新特性

- **语言开关**：设置页新增第一张卡「语言」（`English` / `简体中文`）。切换立即生效，选择存 `localStorage` 并写进服务端配置 `language`，换浏览器/换设备跟着走。
- **链接覆盖**：`?lang=en` / `?lang=zh` 优先于本地选择，方便把中文入口发给别人；`https://m.51pwn.com/?lang=zh&token=…` 两个参数可以并存。

- **不翻译内容**：歌名、歌手、专辑、歌词、字幕、文件路径一律原样——词表只收界面用语，避免把「纯音乐」这类歌词库返回值误当文案。

### 怎么做的（`web/i18n.js`）

- 以**中文原文**为 key 的短语表（338 条），而不是给每个字串起 key。原因很实在：文案散在 `index.html` 的静态标记和 JS 的模板字符串里，起 key 要改近 500 处且容易漏；用原文当 key 只要在**输出点**包一层 `T()`。
- `T(s)`：英文时按**最长短语优先**做子串替换，所以整句、片段、拼出来的 HTML 片段都能覆盖；中文时原样返回。纯文本还会合并因为拼接产生的双空格。
- 静态标记：启动时 `MPI.localizeDOM(document.body)` 走一遍文本节点与 `placeholder/title/aria-label`，原始中文记在 `WeakMap` 里，切回中文可以还原。
- 动态文案：`app.js` / `player.js` / `lyrics.js` 里含中文的字面量已批量包上 `T()`——用词法扫描完成，正确跳过注释、正则字面量、对象键、比较运算与 `case`，避免把「数据」当「文案」翻掉。
- 服务器消息：接口错误传输上仍是中文（保持兼容），前端 `api()` 里过一遍同一张词表，toast 与空状态因此也是英文。

### 如何使用

1. 打开界面 → 设置 → 语言 → 选 `简体中文`（或 `English`）→ 自动刷新即生效。
2. 想直接进中文站：`https://m.51pwn.com/?lang=zh`；英文（默认）：直接进或用 `?lang=en`。
3. 服务端统一默认：`POST /api/config {"language":"zh-CN"}` 或改 `~/.config/mplay/config.json` 的 `language`。

## v1.4.1 · 安全收口：公网访问默认拒绝、SSRF 与路径泄漏封堵

起因是一个很具体的问题：「从互联网打开 `m.51pwn.com`，会不会读到我 Mac 上的非音频文件？」为此把整个对外边界重新审了一遍，先在有 token/无 token 的实例上做了黑盒复现，再改代码、再复测。功能、界面、曲库口径完全不变，只动安全边界。

### 审计结论（有实证）

| 问题 | 状态 | 实测 |
| --- | --- | --- |
| 目录穿透（`/media/../..`、`/cover/..`、`/api/lyric/../..`） | **不成立** | `--path-as-is` 打一串 payload：`mux` 307 归一到 `/etc/passwd`，静态处理器回 404，无文件内容 |
| 读非音视频文件（`~/.ssh`、`config.json` 等） | **不成立** | 索引只收 `audioExts`/`videoExts` 的文件，`/media/{id}` 的 `{id}` 是曲目哈希，路径来自索引 |
| 未鉴权改配置 → 整盘音视频入库下载 | **成立（已修）** | `POST /api/config {"mediaDirs":["/Users/<你>"]}` 返回 200 并生效 |
| 曲库/配置泄漏绝对路径、用户名、配置路径 | **成立（已修）** | `/api/library` 直接回 `path=/Users/…` |
| SSRF：自定义音源/AI 端点可指向本机端口，错误串带响应体前 256 字节 | **成立（已修）** | `/api/search` 回 `ssrf: HTTP 404 404 page not found`（内网接口原文） |
| 反代场景下「打开文件夹」「系统播放器」对本机判定的失效 | **成立（已修）** | 判据是 `Cfg.Addr`，反代时永远是回环 |
| CSRF：第三方网页可让本机接口执行写操作 | **成立（已修）** | `Origin: https://evil.example` 的 POST 原本返回 200 |

### 改了什么

- **公网默认拒绝**（新增 `internal/netguard`）：没设 `authToken` 时，只有「本机直连」放行——对端回环、无任何转发头（`X-Forwarded-For`/`X-Real-IP`/`Forwarded`/`CF-Connecting-IP`…）、非 `Sec-Fetch-Site: cross-site`。经反代/公网一律 `403` 并给出可操作提示。伪造 `X-Forwarded-For: 127.0.0.1` 也不放行（只认「有没有代理头」，不认值）。
- **令牌比较改常量时间**；`/api/health` 保持开放但只回媒体目录**数量**，不再回绝对路径。
- **响应脱敏**：非本机直连时，条目 `path`/`dir`/sidecar `path` 清空、`configPath` 为空、`mediaDirs` 只回目录名、自定义音源的 `headers` 去掉（那里常有 Authorization/Cookie），并新增 `localAccess` 字段。
- **SSRF 双向拦截**：`POST /api/config` 写入时校验 `sources[].searchUrl` 与 `aiBaseUrl`（非法直接 400），出站前（`music.searchCustom`、`identify.Ask`/`Ping`）再校验一次。只允许 `http/https`；解析结果落在 `127/8`、`10/8`、`172.16/12`、`192.168/16`、`100.64/10`、`169.254/16`、`::1`、`fc00::/7`、`fe80::/10` 等一律拒绝。
- **GUI 动作改按请求来源判定**：`/api/pick/folder`、`/api/open` 必须本机直连；`canPickFolder` 在远程访问时恒为 `false`。
- **CSRF 防护**：写方法要求 `Origin` 与本站一致（无 `Origin` 的 curl/桌面壳照旧放行）。
- **启动告警**：非回环监听且没令牌时，日志打出醒目警告。
- **前端**：`?token=` 落地到 `localStorage`（刷新/媒体流都能带上）；遇到 401/403 时弹一次令牌输入框，填对后自动刷新；设置里令牌说明同步。
- **文档**：README 新增「安全模型」整节；API 段落更新鉴权口径。

### 如何使用（如果你的场景是「本机 127.0.0.1 + HTTPS 反代对外」）

1. 打开 `http://127.0.0.1:8737` → 设置 → 访问令牌，设一个够长的字符串（或在 `/etc/mplay/env` 写 `MPLAY_TOKEN=…` 后重启）。
2. 以后从 `https://m.51pwn.com/?token=你的令牌` 进站一次即可，页面会把令牌存进本地，后续刷新不用再带。
3. 没设令牌时直接访问 `https://m.51pwn.com` 会看到 403 与提示文案——这是预期行为，不是坏了。

### 支持的环境

macOS（Intel/Apple Silicon）、Linux（amd64/arm64）、Windows；Go 1.21+ 编译；浏览器 Chrome/Safari/Firefox 任一。

### 验证

- `go vet ./...`、`go test ./...` 全绿；新增 `internal/netguard`（IP 段/来源判定/同源）与 `internal/server/security_test.go`（反代 403、令牌、同源、脱敏）共 9 个用例。
- 黑盒复测（无令牌实例）：带 `X-Forwarded-For` 打 `/api/config`、`/api/library`、`/api/stats`、`/media/*`、`/cover/*` 全部 403；本机直连照旧 200；`/api/health` 仍 200 且不含路径。
- 带令牌 + 反代：`/api/config` 无 `configPath`、`mediaDirs` 只有目录名；`/api/library` 条目 `path`/`dir` 为空。
- SSRF：把 `searchUrl` 指向 `127.0.0.1:8831/api/nope`、`aiBaseUrl` 指向 `169.254.169.254` 均 400。
- 真实浏览器（Chrome）：本机直连 584 条曲库加载、点击播放、歌词条渲染、`errors: []`；再模拟「反代 + `?token=`」同一套流程，584 条、播放正常、`errors: []`；媒体流 Range 请求 `206 / audio/mpeg / 1024 字节`。

## v1.3.0 · 歌词源扩到酷狗 + 纯音乐不再硬配

这一版解决三件事：**华语/翻唱不再找不到词**，**脏标签不再顶掉正确写法**，**纯音乐不再被当成“有歌词”**。
用 584 首真实曲库（资源站下来的脏文件）实测：有歌词 **498/584（85.3%）**，纯音乐占位 48 条全部标成「无歌词，纯音乐」，剔除纯音乐/音效/超短片段后 **498/511（97.5%）**。

### 新特性

**三个歌词源，按顺序、可单独关闭**

| 源 | 默认 | 说明 |
| --- | --- | --- |
| LRCLIB | 开 | 欧美 / 主流华语，带时间轴 |
| 酷狗 | **开（新增）** | 华语网络歌手、翻唱、民乐覆盖最好；搜索 → 歌词候选 → 下载 base64 LRC，频控 900ms |
| 网易云 | 关（新增，可开） | 接口能用但按 IP 限流，实测密集请求后持续 405「操作频繁」，所以默认关闭、代码保留 |

兜底顺序：LRCLIB 全部候选不合格 → 酷狗 → 网易云 → 同名借词（要求 `歌名 ≥0.92` 且（`艺人 ≥0.45` 或 时长差 ≤3s））。

**纯音乐 = 无歌词，不是命中**

- 歌词库给乐器曲返回的「纯音乐，请欣赏」不再当歌词：写 `<缓存>/lyrics/<id>.nolyric.json`，曲库条目多出 `noLyric=无歌词，纯音乐`（不算 `lyricSource`、不进 `withLyric` 统计）。
- 列表角标直接显示「无歌词，纯音乐」，详情页说明原因而不是「没找到歌词」；`GET /api/lyric/{id}` 对这类条目 0.03s 返回结论，不再打网络。
- 启动时自动迁移历史数据：把已经存下来的占位歌词转成结论（实测一次修正 48 条）。
- 顺带修掉「永久 miss 每轮无限重跑」：已出结论的条目移出待缓存列表（48→38）。

**「打开本地文件」→「打开本地文件夹」**

曲库工具条原来的「打开本地文件」升级成「打开本地文件夹」，按环境给两种行为：

- **本机（桌面版 / 本机浏览器）**：弹系统原生目录选择框（macOS `choose folder`、Linux `zenity`/`kdialog`、Windows `FolderBrowserDialog`），选中目录自动加入 `mediaDirs` 并立即扫描，已存在则不重复添加；新增接口 `POST /api/pick/folder`（只对本机回环开放，返回 `{ok,path}`，取消返回 `{ok:false,cancelled:true}`）。
- **纯网页（远程部署 / 无图形会话）**：自动退回浏览器目录选择（`webkitdirectory`），把文件夹里的音视频临时加入播放队列，不写曲库——浏览器拿不到真实路径，无法替服务端扫盘，这一点在提示里写明。
- 单文件入口保留：直接把文件拖进窗口即可播放，不写曲库。
- 能力探测：`GET /api/config` 新增 `canPickFolder` 布尔（是否具备图形会话 + 原生对话框工具），前端据此决定走原生还是浏览器后退方案。

**匹配层修正（提升命中率的主因）**

- `coreTitle`：比对前剥掉 `(Live)/(DJ版)/(女版)/(古琴名曲)/(翻奏)` 等括号附件，版本后缀不再把同一首歌判成两首；再由时长把错版本挡掉（实测 `做你的爱人` 取到 285s 原版，不是 194s 慢摇版）。
- 修复「候选提前判死」：酷狗候选在第一个写法下没过门槛时曾被标记“已看过”，导致反序写法（正确那个）永远不再评估；现在通过校验后才标记（`晚风作酒`、`做你的爱人` 由此命中）。
- `normArtistToken`：抹掉 `003L（桃籽）` 这类序号/括号噪音，与酷狗的 `L（桃籽）、周林枫、三楠` 对得上；`& / , 、 ; | x vs feat ft with -` 都当分隔符取最高分。
- 反序歧义：候选里同时存在 A/B 与 B/A 时，非首选朝向且只有单条记录支持的不认；反序脏条目直接丢弃。
- 时长门槛放宽：`艺人 ≥0.85` 时只扣分不否决（DJ/加长版能命中），否则仍 −20。
- 标签不可全信：标签值先过站点词过滤（`kuwo/kugou/qqmusic/…`）+ `CleanName` 清洗，**只作第一顺位候选**，文件名候选继续参与裁决。
- 省请求：候选上限 6→4、批内 3 并发、全局并发 6、单请求超时 8s→15s、预缓存 2→4 并发、单曲超时 25s→120s。

### 如何使用

- **什么都不用做**：升级后第一次启动就会自动迁移旧缓存，酷狗源默认开启，扫描完成即后台补词。
- **改歌词源**：设置页 →「歌词与字幕」卡片的三个开关（`enableLRCLIB` / `enableKugou` / `enableNeteaseSource`），保存即生效并同步到后台缓存 worker；也可直改 `~/.config/mplay/config.json`，或用 `POST /api/config` 局部更新。
- **看效果**：`GET /api/cache/status` 里 `progress.hit/miss/skipped`（`skipped` 就是判定为纯音乐的条数），曲库工具条会显示 `缓存歌词 3/12`。
- **推翻某条纯音乐结论**：删掉 `<缓存>/lyrics/<id>.nolyric.json`，再 `GET /api/lyric/{id}?force=1` 重新匹配。
- **界面**：纯音乐条目在列表里是「无歌词，纯音乐」角标，详情页给说明；真歌词条目与以前一致（逐行高亮、点击跳转、导出 LRC、手动导入）。

### 支持的环境

| 形态 | 平台 | 要求 |
| --- | --- | --- |
| 服务端 / 网页版 | macOS（Intel / Apple Silicon）、Linux amd64 / arm64、Windows amd64 | 单文件、零 CGO，解压即跑，不需要数据库 |
| 桌面版 | macOS 通用（`MPlay.app`）、Linux x64、Windows x64 | 需要 `urlbox` 外壳：Linux 要有 `webkit2gtk`，Windows 要有 WebView2（Win10/11 一般自带）；macOS ad-hoc 签名，首次右键「打开」 |

- 584 首真实曲库：有歌词 498（85.3%）；纯音乐 48 条全部标记；剔除纯音乐/音效/超短片段后 97.5%；表面命中（含占位）546（93.5%）。
- 抽检内容正确：`做你的爱人`（285s 原版）、`相思`（红豆生南国…）、`晚风作酒`、`Rolling in the Deep (Live)` 均与原曲一致，未出现乱配或串版本。
- 早期 28 条极脏文件名复测 27/28；`go vet ./...` 干净，`go test ./...` 全绿（新增酷狗/网易云/纯音乐三组测试）。

## v1.2.0 · 后台自动缓存歌词 + 文件名多候选解析

这一版解决两件事：**歌词不用等播放才拉**，**脏文件名不再猜错人**。

### 后台自动缓存歌词

- 扫描完成自动触发（`autoCacheLyrics`，默认开），启动时也先跑一轮；设置页可随时开关或点「立即缓存缺歌词的曲目」。
- 独立后台 worker（2 并发 + 600ms 节流 + 429/503 退避重试），与播放共用同一条解析链但互不阻塞；只补「没歌词、没内嵌字幕、缓存未命中」的音频。
- 每首命中立即回填曲库（歌词角标、`lyricSource`、`cueCount`），曲库工具条实时显示 `缓存歌词 3/12`；失败的留在待办，15 秒后的下一轮自动重试。
- 新增接口：`GET /api/cache/status`、`POST /api/cache/run`。

### 文件名多候选 + 歌词库裁决

- 清理规则统一到 `internal/media/guess.go`：站点前缀、括号噪音（码率 / 格式 / 清晰度 / 完整版 / 伴奏 / 站点名…）、括号外裸噪音、`01.` 序号、`- mp3` 尾巴、`feat./ft.`（带词边界，不伤 `Taylor Swift`）；`_` 视作分隔符。
- 不再只猜一种拆法，而是产出排序过的候选队列（各种分隔符、正反朝向、标签、整名兜底），逐个拿去 LRCLIB 用**歌名 ≥0.75 / 艺人 ≥0.55 双门槛**裁决。
- 评分带反序脏条目惩罚（−25）与水印条目惩罚（−30），并给时长接近、带时间轴、社区通用写法加分；`邓紫棋/鄧紫棋`、`G.E.M./GEM` 这类写法差异用字符集重合兜住。
- 回填只改曲库索引（`metaSource=lrclib`），不动用户文件与标签。

### 实测

- 28 条真实脏文件名跑真 LRCLIB：**27/28 命中规范记录**（歌名相似度全为 1.00），原先 4 条「命中错条目」（反序、错歌手版本）全部被纠正；唯一未命中为 LRCLIB 限流所致，单曲复测可命中，后台缓存会自动重试。
- UI 实测（Playwright）：开关关闭时 `tag-cache=已关闭`；打开后角标序列 `0/6 → 1/6 → … → 已缓存 6/6 首歌词`，`/api/cache/status` 收尾 `withLyric 6/6, pending 0, hit 6, miss 0`，前端零 console 报错。

## v1.1.0 · 智能识别歌名

资源站下来的文件常常叫 `abc1234.mp3`、`01. 某站 - 歌手 - 歌名 [320k].mp3`，标签也丢了。这个版本加了三级识别，越往后越贵，所以按顺序短路：

1. **本地候选**：内嵌标签 → 文件名（正序 / 反序 / 去括号）→ 已有歌词第一句，零成本；
2. **歌词库校验**：候选拿去 LRCLIB 打分（歌名 0.62 / 歌手 0.23 / 时长 0.15），≥0.62 算命中，直接把确认过的歌名 / 歌手 / 专辑写回曲库，顺手拉同步歌词；
3. **可选 AI 兜底**：只有前两步没把握才问模型（OpenAI 兼容端点，豆包方舟 / OpenAI / 自建都行）。模型答案还要再过一遍歌词库校验——批量识别只写「校验通过」的，单曲识别要求校验通过或模型置信 ≥0.75，否则只提示建议、不覆盖原文件线索。

- 界面：曲库「识别未匹配」（批量，单次 20 条）、播放器歌词条「识别」（单曲）、设置页「AI 元数据识别（可选）」+「测试连通」；
- 隐私：默认不上传音频；打开 `aiUploadAudio` 后只在手动单曲识别时发前 6 MB 片段，批量永远只发文本；不配 AI 时整套功能退化为本地规则 + 歌词库，不报错；
- 不动你的文件：只改曲库索引（`metaSource=ai`），原音频 / 标签一律不写。

## 下载与使用

### 桌面版

每个桌面包都**解压即用**，不需要装 Go / Rust / Node：

| 平台 | 文件 | 怎么启动 |
| --- | --- | --- |
| macOS（Intel + Apple Silicon 通用） | `mplay-desktop-*-macos-universal.zip` | 解压后双击 `MPlay.app`；首次打开若被 Gatekeeper 拦，右键 →「打开」 |
| Linux x64 | `mplay-desktop-*-linux-x64.tar.gz` | `./start-mplay.sh` |
| Windows x64 | `mplay-desktop-*-windows-x64.zip` | 双击 `start-mplay.cmd` |

包里是 `mplay`（Go 后端 + 内嵌网页界面）和 `urlbox`（Rust + wry 的窗口外壳）。
`mplay-desktop-*-cli.tar.gz` 是同一套东西的裸目录版（不用 .app 时用）。

`mplay-<版本>-<os>-<arch>.tar.gz / .zip` 是**服务端 / 网页版**单文件二进制：

```bash
./mplay -addr :8737 -media /srv/media     # 打开 http://127.0.0.1:8737
```

同一份页面可以部署到 m.51pwn.com（`packaging/nginx-m.51pwn.com.conf`、`packaging/mplay.service`、`packaging/Dockerfile`）。

### 第一次使用

1. 启动后窗口里点「设置」→ 添加媒体目录（音乐 / 视频文件夹），会自动扫描；
2. 同名 `.lrc/.srt/.vtt/.ass` 自动识别，没有的按歌名去 LRCLIB 匹配，视频还会叠字幕到画面上；
3. 也可以把音频 / 视频文件直接拖进窗口播放。

### 已知限制

- 浏览器内核放不了 `.mkv/.avi` 时，桌面版可用「用系统播放器打开」兜底；
- 在线可播放源只有 Apple 30 秒官方试听与公有领域 / CC 音频（Internet Archive、Jamendo、自定义音源），不内置第三方平台的音频地址。

校验：同目录的 `SHA256SUMS`。
