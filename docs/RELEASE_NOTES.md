## v1.4.0 · 曲库四个数字 + 播放器常驻音量/歌词条 + 音频可视化

这一版全是界面：把「有多少东西、有多少有词、还差多少」摆在第一屏，把音量、当前歌词、频谱都放回播放时眼睛会看的位置。功能行为不变，曲库与命中率口径不变。

### 新特性

**曲库概览：四个可点的数字**

| 数字 | 口径 | 点它= |
| --- | --- | --- |
| 全部 | 音视频总数 | 不过滤 |
| 音频 | `kind=audio` 的条数 | `kind=audio` |
| 有歌词 | 音频里有歌词的条数（纯音乐结论不算有词） | `filter=lyric` |
| 待配歌词 | 音频里既没歌词、也还没判成纯音乐的条数 | `filter=pending` |

- 后端 `Stats` 新增 `total / audioWithLyric / noLyric / pending`（`withLyric` 保留为含视频字幕的总数）；`/api/library` 新增 `filter=pending`（音频、无歌词、无纯音乐结论）与 `filter=instrumental`。
- 工具条保留两个补充筛选：`纯音乐`、`全部缺词`。
- 四宫格在 860px 以下变 2×2，480px 以下隐藏副标题。

**缓存歌词进度：圆环 + 百分比**

- 曲库工具条角标改成「圆环 + `63%` + `缓存歌词 24/38`」，圆环按进度收放；鼠标悬停显示完整口径：命中 / 未找到 / 跳过。
- 跑完显示绿色满环与实际命中率，4 秒后收起并自动刷新曲库；设置页的提示也带上本轮百分比。

**音量常驻在进度条一行**

- 音量滑杆从按钮排移到进度条同一行，右侧新增扬声器静音按钮与百分比数字；按钮图标随静音状态切换。
- 响应式：860px 以下隐藏百分比、滑杆收窄；390px 宽度仍然可见可拖（88px）。
- 快捷键同步：`M` 静音/取消，`↑/↓` 每次 5%，双击滑杆回 80%。

**当前歌词条任何时候可见**

- 进度条上方固定一行：当前唱到的歌词 + 译文；前奏/间奏显示 `♪ 前奏 / 间奏…`，纯音乐显示「无歌词，纯音乐」，没有歌词显示「没有歌词」。
- 切到曲库页时，迷你播放条的第二行也用当前歌词代替歌手名。
- 歌词在右侧列表滚动、大字模式、拖进度条时都保持同步。

**音频可视化（跟随真实频谱）**

- 播放区与播放条之间新增一条频谱带：48 根竖条，低频占更多格子，峰值平滑衰减（上升快、下落 0.86 系数），橙金渐变 + 微光。
- 播放时封面/大字/背景光轻微呼吸（4.6s），`prefers-reduced-motion` 下自动关掉。
- **不牺牲播放兼容性**：不把主播放元素绑进 WebAudio（跨域音源绑进去会被静音），改用一只隐藏 `<audio>` 拉同一路流单独分析、输出增益 0；跨域在线音源 / 无 WebAudio / 连续 5 秒无信号时自动退回装饰动画（节奏仍跟播放/暂停）。视频播放时隐藏。

### 如何使用

- 升级即生效，没有新配置项、没有数据迁移。
- 看四个数字：曲库页顶部，点一下就按对应口径筛选；想回到全部再点「全部」。
- 看缓存进度：扫描完成或点「立即缓存缺歌词的曲目」后，曲库工具条右侧出现圆环角标，悬停读详细数字。
- 调音量：播放条进度条右侧，拖动即可；窄屏也在一行内。
- 看当前歌词：不用滚到右侧列表，进度条上方那行就是；切到曲库页看迷你条。
- 频谱：本地曲库播放在线分析真实频谱；在线搜歌的试听/完整音源走装饰动画（跨域拿不到波形）。

## v1.3.0 · 歌词源扩到酷狗 + 纯音乐不再硬配

这一版解决三件事：**华语/翻唱不再找不到词**，**脏标签不再顶掉正确写法**，**纯音乐不再被当成“有歌词”**。
用 584 首真实曲库（资源站下来的脏文件）实测：有歌词 **498/584（85.3%）**，纯音乐占位 48 条全部标成「无歌词，纯音乐」，剔除纯音乐/音效/超短片段后 **498/511（97.5%）**。

### 新特性

**三个歌词源，按顺序、可单独关闭**

| 源 | 默认 | 说明 |
| --- | --- | --- |
| LRCLIB | 开 | 欧美 / 主流华语，带时间轴 |
| 酷狗 | **开（新增）** | 华语网络歌手、翻唱、民乐覆盖最好；搜索 → 歌词候选 → 下载 base64 LRC，频控 900ms |
| 网易云 | 关（新增，可开） | 接口能用但按 IP 限流，实测密集请求后持续 405「操作频繁」，所以默认关闭、代码保留 |

兜底顺序：LRCLIB 全部候选不合格 → 酷狗 → 网易云 → 同名借词（要求 `歌名 ≥0.92` 且（`艺人 ≥0.45` 或 时长差 ≤3s））。

**纯音乐 = 无歌词，不是命中**

- 歌词库给乐器曲返回的「纯音乐，请欣赏」不再当歌词：写 `<缓存>/lyrics/<id>.nolyric.json`，曲库条目多出 `noLyric=无歌词，纯音乐`（不算 `lyricSource`、不进 `withLyric` 统计）。
- 列表角标直接显示「无歌词，纯音乐」，详情页说明原因而不是「没找到歌词」；`GET /api/lyric/{id}` 对这类条目 0.03s 返回结论，不再打网络。
- 启动时自动迁移历史数据：把已经存下来的占位歌词转成结论（实测一次修正 48 条）。
- 顺带修掉「永久 miss 每轮无限重跑」：已出结论的条目移出待缓存列表（48→38）。

**「打开本地文件」→「打开本地文件夹」**

曲库工具条原来的「打开本地文件」升级成「打开本地文件夹」，按环境给两种行为：

- **本机（桌面版 / 本机浏览器）**：弹系统原生目录选择框（macOS `choose folder`、Linux `zenity`/`kdialog`、Windows `FolderBrowserDialog`），选中目录自动加入 `mediaDirs` 并立即扫描，已存在则不重复添加；新增接口 `POST /api/pick/folder`（只对本机回环开放，返回 `{ok,path}`，取消返回 `{ok:false,cancelled:true}`）。
- **纯网页（远程部署 / 无图形会话）**：自动退回浏览器目录选择（`webkitdirectory`），把文件夹里的音视频临时加入播放队列，不写曲库——浏览器拿不到真实路径，无法替服务端扫盘，这一点在提示里写明。
- 单文件入口保留：直接把文件拖进窗口即可播放，不写曲库。
- 能力探测：`GET /api/config` 新增 `canPickFolder` 布尔（是否具备图形会话 + 原生对话框工具），前端据此决定走原生还是浏览器后退方案。

**匹配层修正（提升命中率的主因）**

- `coreTitle`：比对前剥掉 `(Live)/(DJ版)/(女版)/(古琴名曲)/(翻奏)` 等括号附件，版本后缀不再把同一首歌判成两首；再由时长把错版本挡掉（实测 `做你的爱人` 取到 285s 原版，不是 194s 慢摇版）。
- 修复「候选提前判死」：酷狗候选在第一个写法下没过门槛时曾被标记“已看过”，导致反序写法（正确那个）永远不再评估；现在通过校验后才标记（`晚风作酒`、`做你的爱人` 由此命中）。
- `normArtistToken`：抹掉 `003L（桃籽）` 这类序号/括号噪音，与酷狗的 `L（桃籽）、周林枫、三楠` 对得上；`& / , 、 ; | x vs feat ft with -` 都当分隔符取最高分。
- 反序歧义：候选里同时存在 A/B 与 B/A 时，非首选朝向且只有单条记录支持的不认；反序脏条目直接丢弃。
- 时长门槛放宽：`艺人 ≥0.85` 时只扣分不否决（DJ/加长版能命中），否则仍 −20。
- 标签不可全信：标签值先过站点词过滤（`kuwo/kugou/qqmusic/…`）+ `CleanName` 清洗，**只作第一顺位候选**，文件名候选继续参与裁决。
- 省请求：候选上限 6→4、批内 3 并发、全局并发 6、单请求超时 8s→15s、预缓存 2→4 并发、单曲超时 25s→120s。

- **什么都不用做**：升级后第一次启动就会自动迁移旧缓存，酷狗源默认开启，扫描完成即后台补词。

## v1.2.0 · 后台自动缓存歌词 + 文件名多候选解析

这一版解决两件事：**歌词不用等播放才拉**，**脏文件名不再猜错人**。

### 后台自动缓存歌词

- 扫描完成自动触发（`autoCacheLyrics`，默认开），启动时也先跑一轮；设置页可随时开关或点「立即缓存缺歌词的曲目」。
- 独立后台 worker（2 并发 + 600ms 节流 + 429/503 退避重试），与播放共用同一条解析链但互不阻塞；只补「没歌词、没内嵌字幕、缓存未命中」的音频。
- 每首命中立即回填曲库（歌词角标、`lyricSource`、`cueCount`），曲库工具条实时显示 `缓存歌词 3/12`；失败的留在待办，15 秒后的下一轮自动重试。
- 新增接口：`GET /api/cache/status`、`POST /api/cache/run`。

### 文件名多候选 + 歌词库裁决

- 清理规则统一到 `internal/media/guess.go`：站点前缀、括号噪音（码率 / 格式 / 清晰度 / 完整版 / 伴奏 / 站点名…）、括号外裸噪音、`01.` 序号、`- mp3` 尾巴、`feat./ft.`（带词边界，不伤 `Taylor Swift`）；`_` 视作分隔符。
- 不再只猜一种拆法，而是产出排序过的候选队列（各种分隔符、正反朝向、标签、整名兜底），逐个拿去 LRCLIB 用**歌名 ≥0.75 / 艺人 ≥0.55 双门槛**裁决。
- 评分带反序脏条目惩罚（−25）与水印条目惩罚（−30），并给时长接近、带时间轴、社区通用写法加分；`邓紫棋/鄧紫棋`、`G.E.M./GEM` 这类写法差异用字符集重合兜住。
- 回填只改曲库索引（`metaSource=lrclib`），不动用户文件与标签。

### 实测

- 28 条真实脏文件名跑真 LRCLIB：**27/28 命中规范记录**（歌名相似度全为 1.00），原先 4 条「命中错条目」（反序、错歌手版本）全部被纠正；唯一未命中为 LRCLIB 限流所致，单曲复测可命中，后台缓存会自动重试。
- UI 实测（Playwright）：开关关闭时 `tag-cache=已关闭`；打开后角标序列 `0/6 → 1/6 → … → 已缓存 6/6 首歌词`，`/api/cache/status` 收尾 `withLyric 6/6, pending 0, hit 6, miss 0`，前端零 console 报错。

## v1.1.0 · 智能识别歌名

资源站下来的文件常常叫 `abc1234.mp3`、`01. 某站 - 歌手 - 歌名 [320k].mp3`，标签也丢了。这个版本加了三级识别，越往后越贵，所以按顺序短路：

1. **本地候选**：内嵌标签 → 文件名（正序 / 反序 / 去括号）→ 已有歌词第一句，零成本；
2. **歌词库校验**：候选拿去 LRCLIB 打分（歌名 0.62 / 歌手 0.23 / 时长 0.15），≥0.62 算命中，直接把确认过的歌名 / 歌手 / 专辑写回曲库，顺手拉同步歌词；
3. **可选 AI 兜底**：只有前两步没把握才问模型（OpenAI 兼容端点，豆包方舟 / OpenAI / 自建都行）。模型答案还要再过一遍歌词库校验——批量识别只写「校验通过」的，单曲识别要求校验通过或模型置信 ≥0.75，否则只提示建议、不覆盖原文件线索。

- 界面：曲库「识别未匹配」（批量，单次 20 条）、播放器歌词条「识别」（单曲）、设置页「AI 元数据识别（可选）」+「测试连通」；
- 隐私：默认不上传音频；打开 `aiUploadAudio` 后只在手动单曲识别时发前 6 MB 片段，批量永远只发文本；不配 AI 时整套功能退化为本地规则 + 歌词库，不报错；
- 不动你的文件：只改曲库索引（`metaSource=ai`），原音频 / 标签一律不写。

## 下载与使用

### 桌面版

每个桌面包都**解压即用**，不需要装 Go / Rust / Node：

| 平台 | 文件 | 怎么启动 |
| --- | --- | --- |
| macOS（Intel + Apple Silicon 通用） | `mplay-desktop-*-macos-universal.zip` | 解压后双击 `MPlay.app`；首次打开若被 Gatekeeper 拦，右键 →「打开」 |
| Linux x64 | `mplay-desktop-*-linux-x64.tar.gz` | `./start-mplay.sh` |
| Windows x64 | `mplay-desktop-*-windows-x64.zip` | 双击 `start-mplay.cmd` |

包里是 `mplay`（Go 后端 + 内嵌网页界面）和 `urlbox`（Rust + wry 的窗口外壳）。
`mplay-desktop-*-cli.tar.gz` 是同一套东西的裸目录版（不用 .app 时用）。

`mplay-<版本>-<os>-<arch>.tar.gz / .zip` 是**服务端 / 网页版**单文件二进制：

```bash
./mplay -addr :8737 -media /srv/media     # 打开 http://127.0.0.1:8737
```

同一份页面可以部署到 m.51pwn.com（`packaging/nginx-m.51pwn.com.conf`、`packaging/mplay.service`、`packaging/Dockerfile`）。

### 第一次使用

1. 启动后窗口里点「设置」→ 添加媒体目录（音乐 / 视频文件夹），会自动扫描；
2. 同名 `.lrc/.srt/.vtt/.ass` 自动识别，没有的按歌名去 LRCLIB 匹配，视频还会叠字幕到画面上；
3. 也可以把音频 / 视频文件直接拖进窗口播放。

### 已知限制

- 浏览器内核放不了 `.mkv/.avi` 时，桌面版可用「用系统播放器打开」兜底；
- 在线可播放源只有 Apple 30 秒官方试听与公有领域 / CC 音频（Internet Archive、Jamendo、自定义音源），不内置第三方平台的音频地址。

校验：同目录的 `SHA256SUMS`。
